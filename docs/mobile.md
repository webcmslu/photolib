# The phone apps (iOS and Android)

The phone app shows the library of a **Phototek server** (see
[server.md](server.md)): it has no library of its own. It is the same
interface as the desktop app and the browser, built with Tauri for iOS and
Android:

- `src-tauri/src/mobile.rs`: the phone's Rust side, with no commands. The
  interface talks to the server over HTTP, as in a browser (`platform.ts`,
  `api.ts`).
- `src-tauri/src/desktop.rs`: the desktop app, with every command. The heavy
  dependencies (indexer, faces, cameras) are desktop-only in `Cargo.toml`.
- `src-tauri/gen/apple` and `src-tauri/gen/android`: the Xcode and Android
  Studio projects, generated by `tauri ios init` / `tauri android init` and
  kept in git (their build folders aren't).
- `inPhoneApp` in `platform.ts`: the welcome screen opens the last server
  used, or the form to add one.

## Backing up the phone

Settings → "This phone" (`src/lib/PhoneBackup.svelte`), on the phone app:

- **Back Up Now**, or each time the app opens: the photos and videos the
  server doesn't have are sent, in full quality, to `POST /api/upload`. They
  land in `Phones/<the phone's name>/<year>/<month>/` in the library
  (server/src/upload.rs). A photo the library has anywhere (same
  fingerprint) isn't sent twice: the phone asks `known_photos` first.
- **Free Up Space…** removes from the phone the photos recorded as saved
  *and* found on the server at that moment, after the user confirms twice
  (ours, then the system's). iOS keeps them 30 days in Recently Deleted,
  Android in its trash.
- The phone keeps, per server, which of its photos are saved
  (`backup-<server>.json` in its app data), so later backups only look at new
  photos.
- `plugins/photos` reads the photo library: Swift (PhotoKit) on iOS, Kotlin
  (MediaStore) on Android. Originals only, a Live Photo's video included;
  photos kept in iCloud are downloaded first.

Tested on 2026-11-28 in the Android emulator (backup, a known photo skipped,
free up space). On iOS the plugin asks for access as it should; the rest
needs a tap the simulator can't be given from a script, so try it on a real
iPhone. The backup runs while the app is open: backing up in the background
is still to do.

## Versions

The store versions are their own (1.0.0 for the first), apart from the
desktop's 0.1.x:

| Field | Where | Rule |
|---|---|---|
| Public version | `version` in `src-tauri/tauri.ios.conf.json` and `tauri.android.conf.json` | `MAJOR.MINOR.PATCH`; the App Store Connect version carries the same string. |
| iOS build number | `bundle.iOS.bundleVersion` in `tauri.ios.conf.json` | **+1 for every upload** (a reused number is refused). |
| Android versionCode | `bundle.android.versionCode` in `tauri.android.conf.json` | **+1 for every upload.** |

The store listings (descriptions, keywords, What's New) are in
[`store/`](../store/README.md), one file per version, as for CasaFlow and
LetzDrive.

## Develop

```bash
# Once: the Rust targets (done on the MacBook Pro on 2026-11-28).
rustup target add aarch64-apple-ios aarch64-apple-ios-sim \
  aarch64-linux-android armv7-linux-androideabi x86_64-linux-android i686-linux-android

# A Phototek server to look at (any folder of photos):
PHOTOTEK_LIBRARY=~/Pictures/test PHOTOTEK_DATA=/tmp/phototek PHOTOTEK_PORT=8090 \
  PHOTOTEK_WEB=dist cargo run -p phototek-server --manifest-path src-tauri/Cargo.toml

# iOS simulator. VITE_PHOTOTEK_SERVER connects at start (development and
# store screenshots only: the build scripts refuse it).
VITE_PHOTOTEK_SERVER=http://localhost:8090 npx tauri ios build --debug --target aarch64-sim
xcrun simctl install booted src-tauri/gen/apple/build/arm64-sim/Phototek.app
xcrun simctl launch booted lu.webcms.phototek

# Android emulator (10.0.2.2 is the Mac, seen from the emulator).
export ANDROID_HOME=~/Library/Android/sdk NDK_HOME=~/Library/Android/sdk/ndk/27.1.12297006 \
  JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
VITE_PHOTOTEK_SERVER=http://10.0.2.2:8090 npx tauri android build --debug --apk --target aarch64
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

`npx tauri ios dev` and `npx tauri android dev` also work, with live reload.

## Release

1. **Bump** the build number (iOS) or versionCode (Android), and the version
   for a new public version.
2. **Store copy:** `store/<version>.json` written in the three languages,
   `npm run store` passes.
3. **Build and upload:**
   - iOS: `tools/build-ios.sh` (signs with team 7LMT79E5E4 and uploads to
     TestFlight with the App Store Connect API key, as for CasaFlow).
   - Android: `tools/build-android.sh`, then upload the `.aab` in the Play
     Console. The upload key is made once, see the top of the script: **back
     it up**, since Play refuses an app signed with another key.
4. **Test** the TestFlight build or Play internal test on a phone, against
   the NAS **and** the demo server.
5. **Fill the consoles** from the sheet (`npm run store:open`), then submit.
   Set the version's `status` in `store/<version>.json`.
